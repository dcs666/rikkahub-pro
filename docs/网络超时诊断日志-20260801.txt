【超时原因分类】

原因 1: python 网络栈在沙箱内不可用 (主因)
  - 现象: python3 的 urllib / socket / ssl 调用全部挂死;
          socket.getaddrinfo (DNS) 无超时机制, 卡住即无限挂起
  - 证据: 同一时刻系统级测试全部正常:
          * getent hosts api.github.com  → DNS-OK
          * /dev/tcp/<host>/443          → TCP-OK (5 个域名全通)
          * openssl s_client 握手        → TLS-OK, 证书正常
          * git ls-remote                → 一直稳定成功
          * openssl 发 HTTP GET          → 200 OK, token 有效
  - 结论: 沙箱对 python 进程的网络访问受限/异常, 网络本身无问题
  - 解决: 全程改用 openssl s_client 发原始 HTTP 请求, 绕开 python

原因 2: 沙箱间歇性整体卡顿 (偶发)
  - 现象: 有一次连纯本地文件解析(无任何网络)都超时
  - 原因: 沙箱进程调度/负载波动, persistent shell 整体超时
  - 解决: 重试即恢复

原因 3: 脚本 bug 导致的一次 HTTP 400 (非超时, 但属同类排查弯路)
  - 第一次下载脚本用 printf "$req": URL 中 %2B/%3A 等百分号编码
    被 printf 当作格式符吃掉 → 请求被破坏
  - 第二次改 printf '%s': \r\n 不再被解释成回车换行
    → HTTP 请求行非法 → 400 Bad Request
  - 最终 printf '%b' 正确解释转义 → 下载成功, 字节数与 GitHub 记录完全一致

【一句话总结】
  网络没坏; 坏的是 (a) python 联网在沙箱里不可用 (b) 沙箱偶发卡顿。
  换用 openssl 直连后所有请求均一次成功。
